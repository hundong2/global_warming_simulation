# 검증과 개발 절차

[English](../harness-engineering.md) | **한국어** · [문서](../../README.ko.md#문서)

## 재현 가능한 개발

1. 저장소 지침·아키텍처·모델 계약을 읽습니다.
2. 양쪽 개발 기록에 범위가 명확한 계획과 성공 기준을 작성합니다.
3. 수치 상태는 렌더러 외부에 두고 각 결과의 출처와 기준을 보존합니다.
4. `npm run format`, 이어서 `npm run check`를 실행합니다.
5. 브라우저 변경은 `npm run test:e2e`를 실행하고 실제 스크린샷을 확인합니다.
6. 실제 결과·실패한 검사·수정 내용·남은 한계를 양언어로 기록합니다.

## 명령

Node.js 22.12 이상과 저장소의 잠금 파일을 사용합니다.

```sh
npm ci
npm run dev
npm run format
npm run check
npx playwright install chromium
npm run test:e2e
npm run preview
```

`check`는 형식·TypeScript·단위 테스트·프로덕션 빌드·상대 자산 경로·지리 SHA-256·양언어 대응 문서·상호 링크·출처 URL 일치를 검사합니다. 링크 검사는 로컬 파일 대상을 확인합니다. 문서 내 앵커 문구·번역 의미·외부 사이트 가용성은 직접 검토해야 합니다. 저장된 원본 데이터는 네트워크 다운로드 없이 재현 가능합니다.

`test:e2e`는 빌드 후 `http://127.0.0.1:4193/global_warming_simulation/`에서 `dist/`를 제공하여 실제 Pages 하위 경로를 검사합니다. 관련 없는 기존 서버를 재사용하지 않습니다. 같은 포트의 알려진 이전 미리보기를 종료한 후 검사합니다. CI는 `npx playwright install --with-deps chromium`으로 Chromium과 시스템 의존성을 설치합니다.

## 모델 검사

- 독립 IPCC 온도·해수면 종점과 극한 강수 참고 배수.
- 발표된 빙하 질량 종점과 95% 구간 반폭.
- 값의 유한성·순서·상하한 및 해수면·빙하 진행의 단조성.
- ENSO 반대 부호·날짜 변경선 연속성·장기 기후의 독립성.
- 차가운 물·적도·건조한 공기·강한 시어에서 태풍 조건 불충족.
- 대비는 가상 노출을 바꾸고 실제 기온·강수·해수면은 바꾸지 않음.
- 적합도는 무한 증가하지 않고 가정한 최적점을 벗어나면 감소.
- 공유 상태 검증·왕복 복원·알 수 없는 필드·잘못된 수치.

모델 변경을 통과시키려고 참고값을 임의로 바꾸지 않습니다. 테스트 성공이 예측 타당성을 입증하지는 않습니다.

## 브라우저 검사

데스크톱 1440×1000과 모바일 390×844에서 동일한 사용자 시나리오를 Chromium으로 실행합니다. 재현성을 위해 SwiftShader 소프트웨어 WebGL을 사용합니다. 실제 렌더링 프레임 수·실행 중 외부 요청 0건·오류·화면 넘침·설정·전체 레이어·ENSO 색·카메라·재생·일시정지/종료·대화상자·건강/대비·비교·체크 저장·주소 공유·JSON 내보내기·유휴 렌더링·지리 누락·재시도·WebGL 복구를 검사합니다.

`test-results/`의 스크린샷은 실험실·ENSO·빙하·태풍·영향·실천을 포함합니다. 직접 열어 확인해야 하며 DOM 검증만으로 시각 품질을 입증할 수 없습니다. 실제 렌더링 결과를 사용하며 대체 그림은 사용하지 않습니다. 테스트 산출물은 Git에서 제외하고 CI 실패 시 보관합니다. 실제 모바일 GPU·Firefox·Safari는 이 Chromium 검사 범위에 없습니다.

## 과학 기능 확장

실제 홍수·감염병 발생률을 추가하기 전에 인구/지역·시간 범위·평가 항목·자료 라이선스·보정 절차·불확실성·검증을 정의합니다. 백분율 기호로 임의 점수를 확률처럼 표시하지 않습니다. 새 물리 시뮬레이션에는 전문 검토와 독립 참고값이 필요합니다.
